# ПР5. Семантичний пошук у колекції документів

Матеріали до пʼятої практичної роботи. Повний текст завдання, критерії приймання й контрольні запитання — у документі `ПР5.pdf`, виданому до заняття.

## Задача коротко

База знань магазину «Сузірʼя» виросла: замість одного `context.md` — шістнадцять документів у папці `docs/`: правила, інструкції до товарів, відповіді на часті запитання, довідники, внутрішня інструкція. У запит до моделі вони вже не вміщуються, та й не потрібні всі одразу. Потрібен **пошук**, який за запитом користувача знаходить ті кілька фрагментів, що стосуються справи.

Ви будуєте його самі: ділите документи на фрагменти, перетворюєте фрагменти на вектори локальною моделлю ембедінгів, зберігаєте індекс на диску, а за запитом повертаєте top-k найближчих фрагментів з оцінкою схожості. Метадані документів стають фільтрами. Поруч — пошук за ключовими словами по тих самих фрагментах, щоб було з чим порівняти.

Наприкінці — порівняння двох способів на власному наборі запитів із відомими відповідями. У ПР6 цей пошук стане частиною помічника, який відповідає мовною моделлю.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `app/` | Каркас застосунку |
| `docs/` | Колекція документів магазину з метаданими; опис — у `docs/README.md` |
| `ingest.py` | Побудова індексу: читає `docs/`, викликає ваші модулі, зберігає результат |
| `requirements.txt` | Залежності роботи |
| `.env.example` | Зразок налаштувань: модель, top-k, поріг, параметри поділу |
| `check_env.py` | Перевірка середовища: Python, пакети, колекція, завантаження моделі й пробне кодування |
| `compare/` | Порівняння семантичного пошуку з пошуком за ключовими словами |

```
app/
├─ main.py                веб-рівень: сторінка, /api/status, /api/search
├─ documents.py           читання документів, метадані й поділ на фрагменти
├─ embeddings.py          завантаження локальної моделі та кодування тексту
├─ index.py               векторний індекс: збирання, збереження, пошук
├─ keyword.py             токенізація та пошук BM25
└─ templates/index.html   сторінка з двома стовпцями результатів і фільтрами
```

Сторінка надсилає запит із режимом, top-k, порогом і фільтрами та показує результати обох способів поруч з оцінками, джерелом і метаданими. На старті застосунок читає готовий індекс; якщо його ще немає, вебсторінка лишається доступною та пояснює, як його збудувати.

## Початок роботи

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python check_env.py
```

Для macOS і Linux активуйте середовище командою `source .venv/bin/activate`. Значення за замовчуванням достатні для запуску; за потреби налаштування можна скопіювати з `.env.example` у власний `.env`, не перезаписуючи вже наявний файл.

**Запустіть `check_env.py` заздалегідь.** Разом із `sentence-transformers` встановлюється `torch` — це кілька сотень мегабайт, а при першому запуску скрипт завантажує ще й модель ембедінгів (близько півгігабайта). Робити це вперше на занятті — втратити пів пари. Скрипт кодує три речення й показує, наскільки схожими їх вважає модель: перефразування має бути ближчим за стороннє речення.

Ембедінги рахуються локальною моделлю, тому ключ API не потрібен.

Після першого встановлення залежностей і перевірки моделі збудуйте індекс і запустіть застосунок із кореневої папки проєкту:

```bash
python ingest.py
uvicorn app.main:app --reload
```

Далі відкрийте http://127.0.0.1:8000. Якщо індексу ще немає, сторінка пояснить, що спершу треба виконати `python ingest.py`.

## Що очікує сторінка

При відкритті сторінка викликає `GET /api/status` і показує, чи збудовано індекс. Пошук — `POST /api/search` з обʼєктом `{"query": "...", "mode": "both", "top_k": 5, "filters": {"category": "інструкція"}, "threshold": null}`; режим — `semantic`, `keyword` або `both`.

У відповідь сторінка очікує `{"semantic": [...], "keyword": [...], "elapsed": {"semantic": 0.05, "keyword": 0.002}}`, де кожне влучення — `{"score": 0.87, "text": "...", "source": "файл.md", "metadata": {...}}`. Поля `metadata` показуються як є: додасте заголовок розділу — він зʼявиться на сторінці. Якщо назвете поля інакше — змініть сторінку, вона ваша.

## Як влаштована реалізація

| Де | Призначення |
|---|---|
| `app/documents.py` → `split` | Ділить документи за заголовками та абзацами, довгі абзаци — вікнами з перекриттям; додає назву документа й заголовок до фрагментів |
| `app/embeddings.py` → `get_model`, `embed_passages`, `embed_query` | Локально завантажує модель один раз; для E5 використовує `passage:` і `query:`, нормалізує вектори |
| `app/index.py` → `build`, `save`, `load`, `search` | Зберігає NumPy-вектори та JSON-фрагменти з метаданими й моделлю; виконує повний перебір cosine similarity, фільтри й поріг |
| `app/keyword.py` → `tokenize`, `build`, `search` | Ранжує ті самі фрагменти BM25; токенізатор зберігає артикули на кшталт `OR-X2-BLK` |
| `app/main.py` → `api_search` | Єдиний FastAPI веб-рівень: перевіряє запит, режим і фільтри; окремо вимірює два пошуки та повертає зрозумілі HTTP-помилки |
| `compare/` | Містить тестові запити, методику порівняння й результати hit@1/hit@3 |

Параметри фрагментації, top-k та поріг задаються через `.env`. Розмір фрагмента — у символах; семантичний час включає кодування запиту, час BM25 — токенізацію й ранжування. Оцінки BM25 і cosine similarity мають різні шкали, тому їх порівнюють за позиціями результатів, а не за абсолютними числами.

Індекс включає всі документи колекції, зокрема архівні й внутрішні. Фільтр `audience` допомагає досліджувати колекцію, але це навчальний застосунок без автентифікації: перед публічним розгортанням доступ до документів для персоналу потрібно обмежити серверною авторизацією, а не довіряти фільтру від браузера.

Після зміни документів, моделі або параметрів фрагментації виконайте `python ingest.py` повторно. Індекс лежить у кореневій папці `index/` і не комітиться.

## Чекліст самоперевірки

- [x] `python ingest.py` будує індекс з усіх документів `docs/` і зберігає його на диск разом із назвою моделі.
- [x] Фрагменти мають осмислений розмір і межі; у кожного є джерело й метадані документа.
- [x] Запит перетворюється на вектор тією самою моделлю, що й фрагменти; пошук повертає top-k з оцінкою схожості.
- [x] Фільтри за метаданими працюють: `audience`, `status`, `category`, `product`.
- [x] Пошук за ключовими словами працює по тих самих фрагментах і повертає той самий формат.
- [x] Сторінка показує обидва способи поруч: оцінку, джерело, метадані, текст, час.
- [x] Застосунок стартує без індексу й каже, що робити; порожній запит і невідомий фільтр не дають 500.
- [x] Модель створюється один раз; індекс читається при старті, а не на кожен запит.
- [x] Веб-рівень не знає ані моделі, ані формату індексу.
- [x] Порівняння проведено на 12 запитах з очікуваними документами; розмір фрагмента змінено окремо; висновки записано в [`compare/findings.md`](compare/findings.md).
- [ ] Ви можете пояснити кожне ухвалене рішення.
