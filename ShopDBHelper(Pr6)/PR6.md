# ПР6 — RAG-помічник за базою знань

Цей проєкт продовжує пошук із ПР5: гібридний пошук знаходить фрагменти,
а мовна модель формує відповідь лише за ними та повертає посилання на джерела.

## Запуск

1. Створіть середовище й встановіть залежності:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Скопіюйте `.env.example` у `.env` і заповніть `LLM_API_KEY`.
3. Побудуйте індекс і запустіть застосунок:

   ```bash
   python ingest.py
   uvicorn app.main:app --reload
   ```

Відкрийте http://127.0.0.1:8000. `.env` та згенерований `index/` не додавайте
до репозиторію.

## Рішення конвеєра

- Семантичний і BM25-пошук поєднуються Reciprocal Rank Fusion, бо їхні оцінки
  мають різні шкали.
- Сервер завжди додає `audience=клієнти` і `status=чинний`. Інтерфейс може
  фільтрувати за товаром, але не може відкрити внутрішні або архівні документи.
- У контекст потрапляє до чотирьох фрагментів; текст фрагмента не переказується,
  а бюджет оцінюється приблизно як один токен на чотири символи. Позначка
  містить номер, документ, розділ і дату.
- Коли контекст порожній, модель не викликається. Якщо модель відмовилась
  відповідати, відповідь нормалізується до безпечного повідомлення.
- Джерелами відповіді стають лише процитовані фрагменти. Невідомий номер або
  відповідь `found=true` без посилання замінюються безпечною відмовою.
- Поріг схожості лишено порожнім: висновки ПР5 показали, що поріг, який
  відсікав би один негативний приклад, відсікав би й релевантний запит.

## Перевірка набору

Набір із відомими відповідями — у `eval/questions.json`. Команда
`python eval/run_eval.py` проходить питання через увесь конвеєр і записує
результат із фрагментами контексту у `eval/results.json` (цей файл ігнорується
git). Далі вручну звірте очікувані факти, джерела, обґрунтованість і правильність
відмов; зафіксуйте невдачі пошуку окремо від невдач генерації та одну зміну
параметра у `eval/README.md` або власному звіті.
